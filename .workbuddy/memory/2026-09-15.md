## 第三轮查漏补缺：抓到协议级死锁 bug（已全修）
**致命 bug**：IDE tick 等 PENDING_DEV/PENDING_REVIEW，但 watcher 半循环开始即翻 IN_DEV/IN_REVIEW → 施工和监工永远等不到行动状态，全自动循环一步走不动。
修法：确立"行动信号"时序契约——施工 tick 响应 PENDING_DEV 或 IN_DEV；监工 tick 响应 PENDING_REVIEW 或 IN_REVIEW；桥接器保证"先原子写 review-request.md 再翻 IN_REVIEW"。已同步改 tech.md §5/§6、plan.md §3.3、builder-loop.md、supervisor-loop.md。
其余 7 处修复：onError 配置补定义（retry|human，默认 retry）；staleThresholdMin 补配置（默认 0=timeoutMin+5）；supervisor.timeoutMin 上移替代 supervisor.cli.timeoutMin；按模式校验（mode=watch 不强求 apiKey/env）；verdict.json 非原子写入容错（解析失败宽限 3 tick 再判非法）；last_commit 权属厘清（state.json 权威，bridge.md 仅镜像）；Verdict schema 加 round 防陈旧裁决误消费；supervisor-loop 加 bootstrap 降级分支（无守护进程时代办回写，见 review-request.md 恢复即退出）；plan 交接说明 T7→T9 修正 + npm run dev:watch → node dist/cli.js watch。
教训：设计 tick 驱动协议时必须检查"谁在什么时候把状态翻走"——PENDING_* 是瞬时态，IN_* 才是稳态信号。
